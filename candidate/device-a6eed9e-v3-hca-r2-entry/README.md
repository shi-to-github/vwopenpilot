# HCA-r2-entry

设备专用横向择机候选，基线是 a6eed9e / beta2_sharan2 上已部署的 hca-r1 与 diag1。仅替换 hca_timer_reset.py；其余 11 个相关文件按 manifest.json 固定哈希核验。

150 秒开始寻找机会。启动前用 0.4 秒窗口计算请求与限幅值的 RMS，两者均须不超过 60，窗口请求峰值不超过 90。短暂的 60–90 波动可以保留低扭矩判断记录，但真正开始暂停时，当前请求与限幅值仍须都不超过 60。道路条件须连续满足约 0.75 秒。

连续 100 帧、2 秒 standby 才清除软件计时。暂停中的请求超过 90、未来弯道需求、模型过期、驾驶员操作等中止立即恢复控制；240 秒接管兜底与 5 秒重试间隔保留。PID、道路几何门限、Panda、巡航及 UI 未改。软件完成计数不等于直接读到 EPS 内部计时复位。

diag1 被动日志继续记录，新增启动窗口 RMS、峰值、样本数和搜索起点。默认 base 模式不发送自动定速按钮。没有新增设置开关。

本地状态机测试 10 项、安装回退测试 4 项、diag1 回归 4 项通过。已保存道路数据的近似离线对照只检查启动机会：旧策略 3 个计时周期找到首次机会、新策略 4 个；部分周期仍未找到。20 Hz 请求及 10 Hz 几何数据无法严格重建 50 Hz 控制，也不预测两秒暂停能否完成或车辆轨迹。

停车安装、回退及重启使用 tools/manage_c2_hca_r2_entry.py。rollback 仅恢复 hca-r1 timer，保留 diag1；再退 diag1 或 r1 前须按顺序恢复各自基线。

完整部署证据见 ../../docs/HCA_R2_ENTRY_DEPLOYMENT_20261003.md。
