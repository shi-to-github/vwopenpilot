## 实际结果

- 6 次计划暂停全部中止，完整完成 0 次；7 次自然复位包括控制失活，不能充当自动择机完成。
- 6 次软件 240 秒门限事件均记录 steerTempUnavailable/softDisable。触发前两秒 EPS 均为 active；有些其后存在人工 cancel/wrongCarMode，不能把全部控制失活时间都归为自动禁用。
- 原始 EPS 32,930 帧：active 30,720、ready 2,210，没有 rejected 或 fault。
- 各次暂停实际发送 standby 帧数及估算时长：31 帧/0.620 秒、5 帧/0.101 秒、14 帧/0.280 秒、27 帧/0.541 秒、4 帧/0.080 秒、8 帧/0.160 秒。均由 large_raw_demand 中止，未达到连续 100 帧。
- 六次暂停中记录的中心偏差区间合计约 0.019–0.157 米，模型未来横向加速度最高约 0.027 m/s²。邻近数据未显示车道中心边界触发，但这不证明取消中止后车辆的两秒无辅助轨迹安全。

在实际搜索区间 150≤elapsed<240 秒、横向激活且非 standby 的 5,104 个状态样本中，3,848 个（75.39%）首个阻挡是 future_turn_demand，410 个（8.03%）是 entry_peak_above_abort。窗口 RMS 的高值反而只占很少。本次不能用“再改一次 RMS”解释或解决全部失败。

上轮旧分析脚本仍固定按 180 秒统计搜索，此处已改为读取 seek_after_s，并在新 r2 工具中排除 deadline/standby，避免错误呈现 r2 的搜索机会。

暂停中上层 PID 持续 active，EPS ready 时 C2 输出为零，但上层请求仍计算角度误差并波动。六次由请求门限中止，不是 EPS 故障拒绝。请求与车道偏差不是同一物理量；不能将请求峰值等同于失控，也不能将小偏差等同于无需转向。P 项明显参与多个峰值，单纯冻结积分不构成已验证修复。

## 纵向记录

本次包含 base 7,268 条、auto 8,348 条状态。记录有一次人工选择 auto，后出现 ecu_ack_timeout，返回 base。发送回显有 down_short 9 帧、cancel 270 帧；不是只运行横向默认模式。不能由回显认定 ECU 接受调速，也不能把本次超时描述成纵向已经修复。Panda safetyTxBlocked 仅一次从 0 到 1，记录时 controlsAllowed=false，未发现它解释六次暂停中止的证据。

## 修改建议

停止在当前择机状态机上继续叠加阈值，先恢复用户此前反馈有效的固定四分钟、连续两秒 standby 调度作为回归基线，保留现有被动诊断记录。回归时撤销本工程增加的 RMS/峰值/预测门限调度，以及额外的 240 秒 steerTempUnavailable 事件；保留原版 openpilot 的驾驶员退出、CAN/Panda 和 EPS 故障处理。

这不是把 timer takeover 位随手删除，也不是在仍找不到机会的 r2 上无限等待；应整体核对固定基线调度及原版 interface 行为。用户报告旧版有效是回归依据，尚无旧版完整 CAN 日志证明本车 EPS 内部计时重置。固定基线会恢复两秒无主动纠偏窗口，不能称其一直保持主动转向，也不能由本次已中止的短窗口推断完整两秒轨迹。

下一次候选应先核对连续 100 帧 standby 与恢复报文；真正道路结论仍需日志证明。没有将暂停改成未经本车确认的 1.1 秒，没有全局调低 PID，没有改 Panda，没有本轮刷入。任何后续择机研究应与回归基线分开，先完成离线审查，不能再把安装成功当作路测成功。
