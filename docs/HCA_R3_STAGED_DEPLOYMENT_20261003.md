# R3 分阶段择机部署

用户明确要求上线：以 360 秒为预计硬件限制，180 秒前正常控制，180–300 秒择机，300–350 秒提前三秒轻声提醒后执行 1.1 秒 standby，并显示大悬浮窗。预计限制依据历史 EPS 拒绝日志，未读取本车固件内部计数器。

## 最终策略

- 0–180 秒正常控制。自然连续 55 帧 HCA disabled 可清除软件计时；短失活不会清零。
- 180–300 秒寻找当前及未来 1.3 秒窗口：1.1 秒暂停加 0.2 秒预测余量。合格确认约 0.75 秒后执行暂停。
- 300–350 秒评估模型三秒后的 1.3 秒窗口，当前辅助继续。大悬浮窗先显示提示并播放音量比例 25 的短轻提示音，应用回传该次播放结果后开始完整三秒倒计时；这不是驾驶员接管确认。
- 倒计时不断更新预约窗口，窗口变化、驾驶员操作、模型过期、界面/声音服务不可用会取消本次预约，之后重试。
- 真正启动仍核验当前窗口与低请求。暂停发送连续 55 帧 standby，完成软件计数后进入新循环。软件完成不等于直接读取 EPS 内部复位。
- 350 秒仍未完成时提示接管，沿用 interface 的原生软退出事件处理，给预计 360 秒限制留余量。没有到 355 秒无条件暂停、弯道强制暂停或退出后自动开启辅助的路径。

本次把旧 r2 的 240 秒接管门限移至 350 秒；搜索改为 180 秒。取消旧的 RMS/峰值启动筛选以及单次请求超过 90 的暂停中止：当前启动门限为 90/300；暂停中的独立几何/数据/驾驶员条件仍有效，持续 0.2 秒请求达到 270/300 会中止。原有 PID、标准驾驶员与报文速率限制、Panda、EPS、ABS 和定速程序没有修改，默认 base、不启用自动调速。

## 界面与日志

沿用 nl.vwopenploot.probe 包名与原签名，更新此前的 0.5-monitor 独立只读窗为对应 R3 窗。大窗显示软件计时 / 360 秒、阶段、三秒倒计时、暂停剩余时间、循环及完成/中止数、录制状态，可拖动时间区域移动。状态过期或版本不同则显示未确认。

显示数字是软件计时，不是 EPS 内部计时。声音播放 API 成功不等于驾驶员听见；不修改系统音量。系统静音时取消预约，不执行无声的晚期计划暂停。日志继续使用原 diag1 记录器，额外状态包括 delayed_geometry、预约编号、声音回传、取消原因和循环；提示事件保存在 v3_events.jsonl。
