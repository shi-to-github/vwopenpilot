# Panda 模拟 PQ 定速手柄的可行性

## 结论

现有 Dragonpilot `deprecated-beta2/c6` 已经具备大部分通信路径。2026-10-02 复盘确认本车的 C2/Panda 可以成功发送定速手柄 DOWN 帧，但单帧探针没有改变发动机 ECU 内的原厂定速目标；完整按键时序是否能被本车接受仍需验证。具体证据见 [首次探针结果](CRUISE_PROBE_RESULTS_20261002.md)。

这不是制动控制。原厂普通定速降低目标速度时只减少发动机供油，不请求 ABS/ESP 制动；平路上可以滑行或利用发动机制动缓慢减速，下坡时不能保证达到或保持目标速度。

## 当前能否直接启用

不能通过现有 Dragonpilot 设置页、VCDS 编码或“实验纵向控制”直接启用。

这里的“C2/Panda 支持”是指硬件、安全模型、DBC 和原车按钮转发路径已经具备，不代表 `deprecated-beta2/c6` 已经实现了自动加减定速。当前 PQ 代码只会模拟 `Cancel` 和 `Resume`；还需要扩展按钮生成函数、增加目标速度管理器和一个默认关闭的设置项。

Dragonpilot 的“实验纵向控制”走 `ACC_System` 直接加速度请求，并会切换到 Volkswagen long-control safety flag。它不是本文方案，不能用它代替原厂定速手柄模拟。

## 第一应用：视觉前车速度修整

适合先实现以下场景：驾驶员把原车定速设为 120 km/h，C2 确认本车道前车约为 110 km/h，并且距离正在缩短，于是逐次模拟减速键，将原厂定速目标降至约 110 km/h。前车离开或加速以后，再逐次将目标恢复到驾驶员原先设定的 120 km/h。

实现时必须同时保存两个目标：

- `driver_ceiling`：驾驶员最后明确设定的巡航上限，例如 120 km/h。
- `temporary_pcm_target`：根据前车暂时写入原车定速的目标，例如 110 km/h。

如果只读取原车当前目标，那么降到 110 km/h 后就会丢失原来的 120 km/h，前车离开时无从恢复。驾驶员亲自操作手柄、踩刹车、取消定速或关闭主开关时，应立即停止自动按钮发送；驾驶员的新设定同时替换 `driver_ceiling`。

本车没有毫米波雷达也仍有视觉前车数据：该版本 `radard` 在没有雷达点时会用模型的 `leadsV3` 生成 `radarState.leadOne`。第一版应使用持续时间、模型概率、横向位置、相对距离和相对速度共同确认目标，不能仅凭一帧估计或只把前车瞬时速度抄成定速目标。

按钮控制必须闭环运行：发送一次按键，等待 `cruiseState.speed` 或相应 CAN 信号确认原车目标已改变，再决定下一次按键。恢复 120 km/h 时也应逐级增加目标，以限制原车定速的加速突变。若实际车辆不广播可确认的目标速度，自动闭环不得启用，只保留记录模式。

该功能只能作为油门/发动机制动范围内的舒适性调速。距离快速缩短、前车急刹、下坡无法减速或视觉目标不确定时，应报警并停止自动加键，不能把降低定速目标当成制动能力。

## 已确认的源码证据

- PQ 手柄报文为 `GRA_Neu`，CAN ID `0x38A`，长度 4 字节，频率约 50 Hz。
- DBC 已定义 `GRA_Neu_Setzen`、`GRA_Recall`、`GRA_Up_kurz`、`GRA_Down_kurz`、`GRA_Up_lang`、`GRA_Down_lang`、`GRA_Abbrechen`、计数器和发送者字段。
- `carstate.py` 已读取上述全部字段，并保存最新原车手柄报文。
- `pqcan.create_acc_buttons_control()` 已复制原车字段、设置下一个计数器并通过 CANPacker 重算校验和，但当前只暴露 Cancel/Resume 参数。
- `carcontroller.py` 已在原车手柄计数器变化后发送模拟 Cancel/Resume，因此时序、总线选择和反碰撞框架已经存在。
- 2023-04-08 的 Panda Volkswagen PQ 安全模型允许 `0x38A` 在 bus 0 和 bus 2 发送；现行安全模型仍保留这一许可。设备接入后仍需读取实际 Panda 固件版本确认。

## 原厂手柄行为需要实车捕获

公开手册与 DBC 表明该车族具有两组调速动作：

- `Set/Recall` 在定速已激活时通常对应约 -1/+1 km/h。
- `Up/Down` 短按在部分版本对应约 +/-10 km/h，长按则持续改变目标。

不同市场、仪表单位和手柄版本可能不同。不能只依赖公开手册；接机后应记录驾驶员分别操作每一个位置时的 `GRA_Neu` 原始报文，并同时记录仪表目标速度和 `cruiseState.speed`。

## 2023 Dragonpilot 已有地图能力

- `mapd` 能发布 `liveMapData.turnSpeedLimitsAhead`、对应距离和转弯方向。
- `TurnSpeedController` 已能根据曲率目标和距离计算提前减速，默认最低目标约 30 km/h，预减速度参数约为 `-0.8 m/s²`。
- `navd` 会发布导航机动类型、机动距离和路线几何。

当前 `mapd` 不订阅 `navRoute`，它依据当前位置和道路拓扑推断前方路线。在主线与匝道分叉以前，它不一定知道车辆将驶入匝道。因此，不能直接把现有 `turnSpeedLimitsAhead` 无条件转换成手柄减速。面向导航选定匝道，需要把 `navRoute` 几何或可靠的导航机动信息加入路线选择，并先记录误判率。

## 关键限制

1. 原车定速只控发动机扭矩，不控刹车；坡度、风阻和 DQ250 挡位会改变实际减速度。
2. 普通定速接近其最低工作速度后会退出，具体阈值需在本车确认。
3. 当前 5N1 EPS 的横向控制约在 50–55 km/h 以下不可用。若匝道目标低于该阈值，车辆可能在最需要转向时失去横向控制。
4. 导航路线、GPS、地图曲率或限速数据可能错误、过期或匹配到相邻道路。
5. 连续伪造按钮必须等待原车报文计数器并确认目标速度实际变化，不能按估算次数盲发。

## 建议的开发顺序

1. 只读捕获本车每一种手柄动作、计数器、校验和、发送总线及目标速度变化。
2. 确认设备内 Panda 固件确实允许 `0x38A`，不修改安全固件。
3. 制作单次人工触发的 `-1 km/h` 候选，只发送一次并等待 ECU/仪表确认。
4. 增加闭环目标管理：一次按钮脉冲、等待确认、超时停止；刹车、Cancel、主开关关闭、驾驶员手柄操作均立即取得优先权。
5. 地图功能先只显示和记录建议速度，不发送按钮，验证主线/匝道分叉和提前距离。
6. 解决并验证 5N1 横向最低速度问题后，再讨论将地图建议转换为自动按钮操作。
